# Contributing to SCOPEZERO

Thanks for helping test SCOPEZERO. Early feedback is especially useful.

## What to report

- Reproducible bugs and installation failures.
- Incorrect results, false positives and missing evidence.
- Confusing workflows or usability problems.
- Feature requests with a concrete pentesting use case.

## Bug report checklist

Include the SCOPEZERO version, Kali/Python version, steps to reproduce, expected behavior, actual behavior and sanitized logs. Remove domains, IPs, credentials, tokens, cookies, client names and evidence from real engagements before sharing.

## Pull requests

1. Open an issue describing the problem or proposed change.
2. Keep changes focused and explain security implications.
3. Do not add secrets, real engagement data, databases, evidence or generated reports.
4. Include tests or clear manual verification steps.
5. Never weaken scope checks, authorization prompts, host validation or request limits without a documented security review.

Only test systems for which you have explicit authorization. Do not submit exploit code or changes intended for unauthorized access, persistence, credential theft or disruption.
